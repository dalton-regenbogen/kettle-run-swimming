# Kettle Run Swimming

Website for the Kettle Run High School swim team — [kettlerunswim.org](https://kettlerunswim.org).

Plain HTML, Tailwind CSS, and JavaScript. A small build script assembles the pages.

## Quick start

```sh
npm install      # first time only: installs Tailwind
npm run dev      # builds the site, then rebuilds whenever you save a file in src/
```

Then preview `dist/` in the browser. With the VS Code **Live Server** extension, click **Go Live** — it's set up (in `.vscode/settings.json`) to serve the `dist/` folder.

Stop `npm run dev` with **Ctrl+C**.

## The golden rule: edit `src/`, never `dist/`

```
src/                 ← you edit these
  pages/             one file per page (index.html, roster.html, …)
  partials/          pieces shared by every page (header.html, footer.html)
  css/input.css      Tailwind setup and custom CSS
  js/                browser scripts
  assets/            images, logo, PDFs, and the JSON data files
scripts/build.mjs    the build script
dist/                ← generated by the build; published; never edit (not in git)
archive/             old experiments and notes, kept for reference (not published)
```

`dist/` is deleted and rebuilt every time, so any change made there is lost.

## How the build works

`npm run build` (and every rebuild during `npm run dev`) runs `scripts/build.mjs`, which:

1. Empties `dist/`.
2. Copies `src/assets/` and `src/js/` into `dist/` unchanged, plus `CNAME` (the custom domain).
3. Reads each page in `src/pages/`, replaces every include comment with the matching partial file, and writes the finished page to `dist/`.
4. Runs Tailwind to turn `src/css/input.css` into `dist/css/output.css`.

### Include comments

A page pulls in a shared piece with a comment like this:

```html
<!-- include: header.html -->
```

During the build that line is replaced by the full contents of `src/partials/header.html`. Change the partial once, and every page that includes it updates.

To add a new shared piece: create `src/partials/your-piece.html`, then put `<!-- include: your-piece.html -->` wherever it should appear. If the file name is misspelled, the build stops with an error naming the page and the missing file.

### Adding a page

Copy an existing page in `src/pages/` (for example `about.html`), change its `<title>` and `<main>` content, and save. It appears in `dist/` on the next build. Add a link to it in `src/partials/header.html` so visitors can find it.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Build, then rebuild automatically whenever anything in `src/` changes. |
| `npm run build` | Build once with compressed (minified) CSS — the version to publish. |
| `npm run records:meta` | Update `src/assets/data/records-meta.json` with today's date. |

## Updating content

Most frequently changed information lives in JSON files under `src/assets/data/` and `src/assets/rosters/`. Edit the file, save, and the dev build picks it up.

## Publishing

The live site is currently published by GitHub Pages straight from the `main` branch. This `rebuild` branch is not live. Before it goes live, publishing will switch to a GitHub Actions workflow that runs `npm run build` and publishes `dist/`.

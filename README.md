# Kettle Run Swimming

Website for the Kettle Run High School swim team — [kettlerunswim.org](https://kettlerunswim.org).

Plain HTML, Tailwind CSS, and JavaScript. A small build script assembles the pages.

## Quick start

```sh
npm install      # first time only: installs Tailwind
npm run dev      # builds the site, then rebuilds whenever you save a file in src/
```

Then preview `dist/` in the browser. With the VS Code **Live Server** extension, click **Go Live** — it's set up (in `.vscode/settings.json`) to serve the `dist/` folder.

Stop `npm run dev` with **Ctrl+C**.

## The golden rule: edit `src/`, never `dist/`

```
src/                 ← you edit these
  pages/             one file per page (index.html, roster.html, …)
  partials/          pieces shared by every page (header.html, footer.html)
  css/input.css      Tailwind setup and custom CSS
  js/                browser scripts
  assets/            images, logo, PDFs, and the JSON data files
scripts/build.mjs    the build script
dist/                ← generated by the build; published; never edit (not in git)
archive/             old experiments and notes, kept for reference (not published)
```

`dist/` is deleted and rebuilt every time, so any change made there is lost.

## How the build works

`npm run build` (and every rebuild during `npm run dev`) runs `scripts/build.mjs`, which:

1. Empties `dist/`.
2. Copies `src/assets/` and `src/js/` into `dist/` unchanged, plus `CNAME` (the custom domain).
3. Reads each page in `src/pages/`, replaces every include comment with the matching partial file, and writes the finished page to `dist/`.
4. Runs Tailwind to turn `src/css/input.css` into `dist/css/output.css`.

### Include comments

A page pulls in a shared piece with a comment like this:

```html
<!-- include: header.html -->
```

During the build that line is replaced by the full contents of `src/partials/header.html`. Change the partial once, and every page that includes it updates.

To add a new shared piece: create `src/partials/your-piece.html`, then put `<!-- include: your-piece.html -->` wherever it should appear. If the file name is misspelled, the build stops with an error naming the page and the missing file.

### Marking the current page in the nav

The site header is one shared file, so it can't know which page it's on. Nav links in
`src/partials/site-header.html` carry `data-nav-link`, and the build adds `aria-current="page"` to the link whose
`href` matches the page being built. CSS then styles that link (orange text).

### Adding a page

Copy a rebuilt page in `src/pages/` (for example `team-records.html`), change its `<title>`, description, and `<main>`
content, and save. It appears in `dist/` on the next build. Add a link to it in `src/partials/site-header.html`
(with `data-nav-link`) if it belongs in the main nav.

Rebuilt pages use `head.html`, `site-header.html`, and `site-footer.html`. Pages not yet rebuilt still use the
older `header.html` and `footer.html`.

### The 404 page

`src/pages/404.html` is shown by GitHub Pages for any address that doesn't exist — at that address. It starts its
`<head>` with `<base href="/">` so its relative links (`./css/output.css`, `./roster.html`) still resolve from the
site root. Other pages don't need this.

## Updating content

Most frequently changed information lives in JSON files under `src/assets/data/` and `src/assets/rosters/`. Edit the file, save, and the dev build picks it up.

- **Team records:** edit `src/assets/data/records.json`, then run `npm run records:meta`. To tag a record, put
  short text in its `RecordBadge` (e.g. `"State Record"`); leave it `""` for no tag.
- **Meets and results:** one file per season in `src/assets/meets/` (e.g. `meets-2025-2026.json`), listed newest
  first in `meets-index.json`. The Meet Schedule page shows the newest season; the Results page has a season picker.
  - Times are 24-hour (`"18:00"` shows as 6:00 PM). Update `"updated"` to today's date after schedule changes.
  - A meet that isn't happening: add `"status": "canceled"` and an optional `"statusNote": "Weather"`.
  - After a meet, add its `"results"`: for a dual meet, each opponent's score as
    `{ "vs": "BDHS", "us": 90, "them": 130 }` (`vs` is the opponent's `short` name, `us` is Kettle Run); for a
    championship, `"place"` and an optional `"standings"` list of team names. `"pdf"` is the full-results link
    (or `""`). See any meet in `meets-2025-2026.json` for the exact shape. The season summary (record, win %,
    streak, postseason places) is counted from these automatically.
  - New season: copy the file, rename it (`meets-2026-2027.json`), replace the meets, remove the results, and list
    it first in `meets-index.json`.
- **Practice:** `src/assets/data/practice-schedule.json`. Each practice has a `status`: `"normal"` shows
  "Regular practice" under the date, `"off"` crosses the date out and shows "No practice". (The `note` field is
  kept in the data but not shown.) The "Standard practice schedule" line is worked out from the practices.
- **Important dates (home page):** `src/assets/data/importantDates.json` — `seasonLabel` and a list of
  `{ "date", "name", "details" }`. Once every date has passed, the home page says the next season's dates are
  coming, so replace the list when the new season's dates are set.
- **Roster:** each season is a file in `src/assets/rosters/` (e.g. `roster-2025-2026.json`). Add a new season's
  file and list it first in `roster-index.json`; the newest season shows by default. Put `"Captain"` in a
  swimmer's `roles` to show the Captain badge.

### The home page follows the season

`src/js/home.js` decides what the "Right now" card shows from the meet and practice data:

- **Preseason** (before the first practice, or from August after last season ended): Join the team.
- **In season** (first practice → last meet): this week — next meet, this week's practices, latest result.
- **Offseason** (after the last meet, until August): a recap of the season that just ended.

To preview another time of year, add `?date=2026-01-14` to the page address (works on Meets and Practices too).

### Photos

Home page photos live in `src/assets/photos/`. Phone photos are about 3 MB each — far too big for a web page — so
make a web-sized copy first. macOS has a built-in tool for it, `sips`:

```sh
sips -Z 1200 -s format jpeg -s formatOptions 60 ~/Desktop/IMG_1234.jpeg --out src/assets/photos/IMG_1234.jpg
```

`-Z 1200` shrinks the longest side to 1200 pixels; `formatOptions 60` is the JPEG quality. That brings a photo to
about 150–300 KB. Then add an `<img data-slide …>` line for it in the carousel in `src/pages/index.html`, with
`loading="lazy"`, the `opacity-0` class, and an `alt` that describes the photo. The full-size originals are kept in
`archive/photos-original/` (not published).

> While `npm run dev` is running, don't also run `npm run build` — both rebuild `dist/` and can wipe out each
> other's files. The dev watcher already rebuilds on every save.

## Publishing

The live site is currently published by GitHub Pages straight from the `main` branch. This `rebuild` branch is not live. Before it goes live, publishing will switch to a GitHub Actions workflow that runs `npm run build` and publishes `dist/`.
